## Top 5 Highest-Impact Gaps

1. **No optimistic concurrency + full-row rewrites (Correctness — all 3 companies, MO/purchasing/invoices):** `executeWithLock_:441` is short-lived append lock only; `updateRowByCriteria_:841` rewrites entire rows. Two concurrent editors → silent last-writer-wins loss of whole row. Add version/CAS check and make `patchRowByCriteria_:887` the default.
2. **Linear scans in hot paths, shared Map index unused (Performance — all companies, grows with data):** `getRecordsByPk_:1111` exists but only Assessment uses it; TC/TL/VF handlers `find/forEach` over `getAllRecords_` on every save. Route hot lookups through memoized maps.
3. **Duplicated, unlock-guarded invoice numbering in TC/TL (Correctness — finance, 2 companies):** `TopLight:nextInvoiceNumber_:1983` + `TopChemical:3505` full-scan + no lock vs correct `ValleyFoods:nextInvoiceSeq_:9547` (persisted counter + lock precondition). Concurrent saves can mint duplicate numbers. Centralize one locked generator.
4. **No central state machine + scattered validation (Correctness — all doc types/companies):** `changeValleyMfgStatus_:6950`, `approvePurchasing_:899`, `validateSales_:2008`, `validatePurchasingHeader_:978` each enforce fragments. Invalid Draft→Locked jumps and unvalidated writes pass on new routes. One transition table + one pre-write validator.
5. **Manual audit logging; SystemLog insufficient alone (Compliance/correctness — all companies):** No `before/afterWrite` hooks; `logSystemAction_:1464` stores whole `result.data` without old/new or reliable `RecordID`; true row truth in `ERP_Record_History:1318-1342` depends on each handler remembering `logHistory_`. Missed call = gap. Add guaranteed `afterWrite` hook and link `SystemLog ↔ ERP_Record_History` via `record_uid`.
