# ✋ NON-REGRESSION — the rule that shapes every edit

**R-1. Every behavioural change is a fallback that only fires when the current path has already
failed.** Where the code opens a window today, it opens a window exactly as today; the new branch is
reachable only when `window.open` returned `null`. If the current path succeeds, the code path is
byte-for-byte what runs now.

**R-2. Every CSS change is scoped so that at ≥ 600px the computed style is identical to today.**
Mobile-first: the phone rule is the base, and the `@media (min-width: 600px)` tier restores the
*current* declarations verbatim. Prove it in `s15` by diffing declarations against the pre-change
revision, the way `s14` section 5 does.

**R-3. Print output is unchanged on every platform.** Anything that reaches paper today must reach
paper identically after this run.

**R-4. No platform sniffing.** No `if (isIOS)`. Nothing keyed on the user agent. Fixes are
feature-detected (`window.open` result, `window.closed`) or gated on `(hover: none)` / width, so
Android and Windows never enter the new branches. **Note:** `Client_Helpers.html` already reads
`navigator.userAgent` in `SESSION.saveCurrentView` for a device label — that is pre-existing and
unrelated. Do not add a second one, and make your `s15` assertion tolerate that one known site.

**R-5. If you cannot make a change satisfy R-1…R-4, do not make it.** Write it on the owner
checklist as "needs a device to decide" instead.

**D-6. Phase 5 — the row menu's outside-click, in CSS, with no JS change.** The menu closes from a
`document` click listener (`UI_Components.html` ~L303). iOS Safari does not synthesise a click for a
tap on a non-interactive element, so tapping empty page space does not close it. The fix is one
rule:

```css
@media (hover: none) { body { cursor: pointer; } }
```

That is the documented way to make iOS deliver the click. It is gated on `(hover: none)`, so a
desktop mouse never sees a changed cursor, and on a touch device there is no visible cursor to
change. No JavaScript moves, so no listener can double-fire. Put it next to the existing
`(hover: none)` blocks, not in `CSS_Tokens.html`.

## Traps this repo has actually sprung

1. **A backtick inside `UI_Components.html` is a syntax error that blanks every page.** Its CSS
   lives inside a JavaScript template literal. Do not put one in a comment or a selector.
   `parse_pages.js` catches it immediately; `ui_check` C11 exists for it.
2. **`node tools/ui_check.js` rewrites `design_preview/_sources.js`.** Restore it before committing.
3. **The Bash tool mangles backslashes in heredocs and breaks on Arabic literals.** For any content
   with Arabic text, CSS selectors or nested quoting, use the `Write`/`Edit` tools, or write a
   Python transform with `Write` and run it. **Do not fight the heredoc.** Make every replacement
   assert it matched exactly once, and write nothing if any assertion fails.
4. **An unanchored string match can be a substring of a deeper-indented copy.** `"    .foo { … }"`
   matches inside `"      .foo { … }"`. Anchor on the newline.
5. **`git commit` without a pathspec commits another session's staged files.** See Phase 0.
